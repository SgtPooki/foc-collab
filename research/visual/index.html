FOC Capability Ladder

Filecoin Onchain Cloud (FOC) is paid, provable storage with programmable rules: contracts decide who may write to a data set, and payments for storage happen on-chain where anyone can verify them.

This page answers one question: what categories of application can FOC power as the only backend (no app server, no database), and which specific platform investments open the next category. It exists to inform which of those investments we prioritize. Examples are labeled LIVE (running on the calibration test network today), PROTOTYPED (mechanics proven, product not built), or CONCEPT (design on paper, mechanics verified against shipped contracts).

TIER 1 · BUILDABLE TODAY

Serverless apps for participants we onboard

The per-data-set access rules shipped in August (live on the calibration network; mainnet release in progress this week) let a contract govern who writes what into a data set. That is enough for real multi-user applications, with one honest limit: participants have to be set up by the operator today, because the SDK has no self-serve onboarding path yet. Tier 2 removes that limit.

Capabilities available now

Shared state every browser replays identically Anyone can fund an app's storage account, with attributed receipts Write rules enforced by contract, not by a moderator Deletion and shutdown vetoed until a chosen date Public reads over a CDN

Examples

  • LIVETurn-based games, Words-with-Friends style Running now on calibration: a two-player game where every move is a signed record, both browsers compute the same board, and there is no game server. The 30-to-60-second move latency suits turn-based play. Ask us for the link.
  • CONCEPTA community Tamagotchi that eats money A virtual pet whose health bar is the real funding balance of its own storage. Feeding it is a payment; every feeding is publicly attributed; if funding runs out, the protocol gives about 30 days before storage providers stop being paid and may delete it. All the mechanics exist on-chain today; this needs only a web page.
  • PROTOTYPEDHand-off chains with signed receipts, DocuSign-style Work passes between people or AI agents; each step is signed, ordered, and verifiable by an outside party. The record mechanics are the same ones the live game uses; today the participants must be pre-arranged.
  • PROTOTYPEDWrite-once records, like S3 Object Lock An access-rule contract can refuse both deletion and shutdown until a set date. At the current price list, $1,000 funds a terabyte for roughly 16 years, and the balance is publicly checkable. Assumes today's pricing; storage prices move.
TIER 2 · ONE ROUND OF TOOLING AWAY

Open participation: strangers join from a link

The contracts already allow public, rule-governed writing. Three tooling gaps keep it invite-only: the SDK has no path to the new access rules, records cannot be searched or filtered without downloading everything, and the reference contract for sponsored public writing was reverted for release timing and needs restoring. This is SDK work, not protocol work.

Capabilities this adds

Anyone with the link contributes, under contract-enforced limits Search and filter at consumer scale Live activity feeds instead of polling Embeddable views for any website

What that opens

  • CONCEPTAn r/place-style public canvas A shared canvas the whole internet can paint, one pixel per person per time window, with the cooldown enforced by contract. The full history replays as a timelapse because the canvas is an append-only record.
  • CONCEPTConference artifacts funded by the ticket Attendees check in and contribute to a collective piece that is then stored for decades, paid from a slice of the ticket price. No partner lined up yet; the mechanics are verified.
  • CONCEPTComments on any static page, Disqus without the server Viewers of a published page leave notes that persist and overlay on the page. This is the use case the whole line of work started from.
  • CONCEPTCommunity playlists and queues Anyone can add to a shared queue; the contract enforces what kinds of entries are allowed and how often each person can add.
What has to be built, and where
  • SDK support for the access-rule contracts (synapse-sdk)
  • Indexed reads: list and filter records by label without downloading everything (SDK surface over events indexers already capture)
  • Restore the sponsored-public-writing reference contract (filecoin-services; merged in August, reverted for release timing)
TIER 3 · PLATFORM FEATURES AFTER THAT

Economies inside the apps, at consumer scale

With tier 2 in place, four platform features turn open applications into products. Each also upgrades every example above: the Tamagotchi gains paid adoptions and cosmetics, the public canvas gains paid features and event-scale crowds, and the hand-off chain gains escrowed payment per step and AI agents that participate on their own. That last combination, verifiable multi-party work with no coordinator to run or trust, is the shape our agent go-to-market is built around.

Capabilities this adds

Paid actions: entry fees, upgrades, bounties, auctions Passkey sign-in, no wallet or crypto knowledge Crowd-scale writes at ~$0.003 per action AI agents that pay and get paid autonomously

What that opens

  • CONCEPTApps that fund their own storage Entry fees and upgrade purchases flow to the account paying the storage bill, so the app covers its own costs and the operator never holds user funds.
  • PROTOTYPEDWork marketplaces with built-in escrow Payment for a step releases when the next participant accepts the work, with a platform fee taken natively. The shipped payment rails support this composition; it needs a hardened reference contract, not new protocol.
  • PROTOTYPEDRetention as a product The tier 1 write-once pattern packaged so a compliance buyer audits a product, not a bespoke contract: pay once, retain provably for N years.
What has to be built, and where
  • Charge-the-writer payment hooks and a reference escrow contract (filecoin-pay, filecoin-services)
  • Passkey signatures proven on-chain (the access-rule design anticipates them; gas cost needs measuring)
  • Batched writes carrying many individual signatures in one transaction (filecoin-services)
  • Payment permissions for delegated agent keys (today only the owner wallet can pay)

The ask

  1. SDK path to the access-rule contracts (opens all of tier 2)
  2. Indexed reads (makes tier 2 usable at consumer scale)
  3. Payment hooks plus the escrow reference (opens tier 3 economies)

Known limits and risks

Writes take 30 to 60 seconds, so real-time apps are out of scope. Open participation invites spam and abuse; rate limits and blocklists are contract-enforceable, but content moderation policy is ours to define. Reads bill the app's account, so a popular free app is a bandwidth cost with no revenue unless tier 3 lands. Cost figures use the current calibration price list and move with it.

Every status was verified against the shipped contracts (filecoin-services main, calibnet v1.4.0 deployment) and synapse-sdk 1.2.1 on 2026-09-01.
